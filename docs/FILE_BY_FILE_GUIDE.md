# File-by-file walkthrough (Day 1)

| File | Responsibility | Reason |
|---|---|---|
| `pyproject.toml` | PEP 621 package metadata, dependencies, pytest/Ruff/mypy config, hatchling backend | Single standard Python project declaration |
| `.python-version` | Pins Python 3.12 for uv | Predictable interpreter |
| `uv.lock` | Resolved Python dependencies after local bootstrap | Reproducible CI and Docker builds |
| `src/engipilot_ai/__init__.py` | Python package marker | Avoid sys.path hacks |
| `src/engipilot_ai/main.py` | FastAPI factory, startup/shutdown, request IDs | Thin composition root |
| `src/engipilot_ai/core/config.py` | Validated environment settings | No scattered `os.environ` calls |
| `src/engipilot_ai/core/database.py` | Lazy async SQLAlchemy engine | Connection lifecycle separate from API |
| `src/engipilot_ai/api/health.py` | Liveness vs database readiness endpoints | Reliable health behavior |
| `tests/` | pytest unit / API tests | Quality gate from Day 1 |
| `apps/web/package.json` | React/Vite dependencies and scripts | Standard Node package |
| `apps/web/package-lock.json` | Generated by npm install | Deterministic `npm ci` |
| `apps/web/src/App.tsx` | Working API connectivity UI | Simple vertical slice, no fake screens |
| `apps/web/vite.config.ts` | Dev proxy `/api` → FastAPI | Same-origin browser requests |
| `apps/web/eslint.config.js` | JavaScript/TypeScript lint rules | Prevent common frontend mistakes |
| `compose.yaml` | Local PostgreSQL only | Keep local database easy to run |
| `Dockerfile.api` / `Dockerfile.web` | Shippable API/web containers | CI builds, CD publishes |
| `compose.demo.yaml` | Optional local container demo | Tests containers together, not production |
| `infra/nginx/default.conf` | Web SPA + reverse proxy `/api` | Browser/server routing in container mode |
| `.dockerignore` | Exclude `.env`, `.git`, `.venv` etc from build contexts | Avoid shipping secrets and huge contexts |
| `.env.example` | Local config example | New developer knows keys without seeing secrets |
| `.gitignore` | Ignore generated and private files | Keep repository clean |
| `.github/workflows/ci.yml` | Automated quality and Docker build | Every PR gets quality gates |
| `.github/workflows/release.yml` | Publish tagged images to GHCR | Learn controlled delivery, not auto-prod deploy |
| `.github/pull_request_template.md` | PR review checklist | Consistent engineering communication |
| `docs/architecture/V0.md` | Architecture constraints and planned module | Persistent design record |
| `docs/decisions/` | Document decisions/alternatives | Explain WHY choices were made |
| `scripts/bootstrap.sh` | Setup, lock and install, run checks | Repeatable local onboarding |
| `scripts/check.sh` | Mirror local CI quality commands | No surprises on GitHub |
| `scripts/check_database.py` | DB smoke test | Verify DB is actually reachable |
| `Makefile` | Short shell targets | Convenience, not logic hidden in Make |

## Important clarification about the starter

This is a **production-oriented development foundation**, not a finished production service. It contains **no user/auth/project/organization/AI implementation yet**. In the next branches we will add organizations/projects and authenticated GitHub App integration, then the AI PR review engine and the web UI.
