# V0 Architecture: Multi-tenant AI Code Review

## Intended user journey

Organization owner -> Create organization -> Create project -> Connect approved GitHub organization via app -> invite/approve members -> authorized developer selects PR -> runs AI review -> receives evidence-backed findings.

## Implementation boundary

- **Day 1**: independently runnable API/web shells, local DB service, tests, CI and reproducible setup.
- **First feature task**: tenant identity data model and migrations, audited project scope, permissions.
- **Next**: authentication/invitations, never custom password/MFA implementation in the pilot.
- **Next**: GitHub App repo discovery, installation management, authorization, and private PR access.
- **Next**: actual AI review engine, output schema and validation, evaluation dataset.

### Isolation / authorization requirements

1. Do not equate repository installation access with human user authorization.
2. Organization administrators inherit project administrative capabilities **inside EngiPilot**, not at the Git provider.
3. Access to a PR requires: authenticated user, active organization membership, project permission, repository mapping, verified Git-provider entitlement and organization policy.
4. Imported GitHub users are *pending identities*, not automatically granted active accounts or permissions.
5. Repository contents and diffs are untrusted. Reject prompt injection and do not execute source code during review.
6. AI provider selection and data export must be company-authorized before ingesting confidential code.
7. Never log raw source code, access tokens, or source diffs by default.

## Logical design

React web -> FastAPI API -> application services -> adapters (GitHub, model) -> PostgreSQL.
LangGraph review workflow and background workers arrive when implementing AI jobs. No unused future services are created on Day 1.

## First demonstration gate

Authenticated authorized developer reviews an approved private PR; evidence-backed findings tied to commit SHA, skipped-file limitations and evaluation metrics are shown. This gate is **not** implemented by the Day 1 scaffold.
